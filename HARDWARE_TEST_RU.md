# Исправления и испытания 17 ноября 2026

I2C v7.2.1, commit95ae8fd: сигнатуры register read/write и buffer read совпадают с использованными APDS вызовами, статусы0..6 сохраняются. Изменены оба manifest pin. I2C internals не изменялись.

## Устройство COM6

WCH-Link flash/verify успешно; UART115200. ID=0x9E. С исправленным GCONF2=0x61 измерены пакеты RAW255/255/255/255; распознавание отсутствовало из-за насыщения. После выбора по ID профиля1x/12.5mA (до boost, GCONF2=0x19) FIFO в покое0, GS0. Это наблюдение конкретной платы и выбранный рабочий профиль, а не доказательство отличающейся карты регистров всех0x9E. Профиль APDS_CLONE_9E_PROFILE отключаемый; все4 разрешённых ID сохранены.

Проверено на железе: чтение config, переполнение GS03/level32 -> recovery error2 -> GS00/level0; sleep/wakeup вернулиtrue. С низким профилем boot self-test GS00/level0 без overflow.

Пользователь подтвердил последовательность горизонтальных лево/право и вертикальных вверх/вниз. В60-секундной записи17 результатов: LEFT4, RIGHT5, UP4, DOWN4; порядок осей соответствует движению. Это не измерение95% accuracy и не полный размеченный набор20 независимых жестов. Ориентация обозначений согласована с используемыми движениями, калибровка поворота платы отдельно не реализована.

На окончательной прошивке безDEBUG/HW_TEST записана минута покоя: только начальные строки ID9E/ready, без жестов, ошибок и повторного boot. Подробные UART-логи в test/evidence. Первая неуспешная запись с насыщенным профилем не считается успешно пройденным тестом.

Объектная сумма доGC не равна вкладу linked library: неиспользуемые публичные функции выбрасываются. Итоговая Flash включает startup/I2C/framework/данные. Logger поддерживает только используемые %d/%u/%X/%02X/%%, требует настроенный UART. Стек readGesture96B, calibration64B по .su; это кадры, не полный watermark.

## Проверки и границы

Шесть сборок с -Wextra -Werror на project sources: default7940/380; polling7440/368; no-cal7228/376; DEBUG8364/380; external-ISR7860/380 (только build, приложение обязано предоставить ISR); OWN0 7824/376 (Flash/RAM B).

Четыре host suites:66193/66193/66193/644 assertions, failures0. Исходник драйвера включается непосредственно; I2C замокан только по public API. Проверены исправления FIFO/GFOV/abort, timeout, четыреID, profile0x9E, поля конфигурации, все уровни1..32 и255, ошибки транзакций, calibration fallback/clamp, NULL и математика (isqrt exhaustive). Запуск из корня: test/host/run.ps1. Нет полного branch coverage, аппаратного сбоя питания/I2C, тестов каждого клона или длительного soak. Устойчивость доказана в перечисленных сценариях, не сертифицирована для всех условий.

Основные изменения: FIFO clear/resync после abort/wakeup; NONE+TIMEOUT вместо partial decode; cache thresholds commit после обеих записей; runtime GIEN policy сохраняется; GPIO clock; bounded INT-level polling вместо потерянного WFI и выбрасывания следующего жеста. Это повышает активностьCPU. Для общего SysTick нужны OWN0 и APDS_DELAY_MS hook; default SDK Delay_Ms всё ещё использует SysTick. GIEN RMW не атомарен относительно автономного GMODE: не переключать посреди жеста.

На устройство последней загружена штатная сборка7940B, подробные диагностические флаги выключены. Для длительной квалификации нужны часы/сутки с размеченными жестами, условиями света/расстояния и fault injection.


## Второй экземпляр: ID0xA8

Проверен через COM6 с той же I2C7.2.1. Generic GCONF2=0x61 (8x/100мА до boost) не насыщал фон:1863 пакета в покое, насыщенных0; типичные U45..53,D4..8,L18..25,R55..62. Однако GEXTH30 удерживал engine активным, GS03/level32 после задержки. Пробный вход/выход100/80 дал idle0 и32 proximity samples (median22), но большинство жестов имело1..3 valid packets, только4 DOWN. Порог70 и persistence4 не решили проблему: в следующей разреженной RAW-записи43/55 пакетов движения насыщены, направления искажены. Эти неудачные варианты не сохранены в defaults.

С GGAIN2x/GLDRIVE25мА до boost (GCONF2=0x31) и исходными порогами50/30 записано ровно20 результатов:5 LEFT,5 RIGHT,5 UP,5 DOWN, сначала горизонтальная группа, затем вертикальная. Калибровка32samples median24, idleGS00/level0, sleep/wakeup успешны. Разреженная RAW-запись:61 наблюдение,29 насыщенных пиков; насыщенные пакеты отбрасываются, оставалось4..27 valid packets на жест. Поэтому нельзя заявлять отсутствие насыщения на близкой дистанции, а min4 в части вертикальных жестов имеет небольшой запас. Проверялось расстояние порядка5..10см по инструкции пользователю; инструментально расстояние не измерялось.

Сохранён отключаемый APDS_CLONE_A8_PROFILE по ID, профиль9E сохранён. Для original/прочих ID register mapping не менялся. Профиль board-specific и не доказывает иное устройство регистров всехA8. APDS_RAW_DEBUG печатает лишь каждый8-й dataset, чтобы уменьшить вмешательство UART. Непроверенный persistence-tunable удалён.

Default Flash7952Б (+12), RAM380Б (без роста). Host-регрессия4 suites:66197/66197/66197/648 checks, failures0; добавлены init/recovery проверки A8profile. UART-логи с префиксомa8 в test/evidence. Последняя штатная сборка безDEBUG/RAW/HW_TEST прошита наA8; результат финального idle-прогона записывается отдельно.

Финальный A8 idle60с: только один boot/ready, жестов и сообщений об ошибках0. Прошли default и6 дополнительных Wextra/Werror сборок, включая оба profiles=0. Итоговый объект apds9960.o text3502Б, +12Б; EXTI234Б, logger436Б. Это не длительный soak и не подтверждение всех дистанций/условий света.


## Третий экземпляр: ещё один ID0x9E, проверка исправности

Подключение/питание по подтверждению пользователя те же, других I2C устройств нет. Сначала удалось по100раз прочитать ID и по32раз записать/прочитать WTIME на каждой из частот400/100кГц, ошибок0; init и краткий опрос FIFO успешны. Это только короткая проверка, не подтверждение исправности.

В длительной обычной работе повторяется ARLO(status5), в том числе при polling безEXTI и с I2C_ATOMIC_CRITICAL=1. Переход на100кГц не помог. При APDS_LED_BOOST=0/APDS_LED_CURRENT=3 короткий запуск/calibration был успешен, но последующий65-секундный оптический прогон завершился массовыми ошибками5/6, ни одного FIFO RAW/жеста получить не удалось. Кратковременное улучшение на малом токе НЕ означает исправление и не доказывает единственную причину в питании. Возврат обычного тока также воспроизвёл сбой.

После выполненного пользователем полного снятия питания i2c_init вернул I2C_ERR_RECOVERY(6) на400 и100кГц. Заключительная проверка GPIO: SDA=0,SCL=1 на обеих частотах после неуспешного recovery, то есть шина не освобождена. apds_shutdown по I2C тоже не прошёл.

Заключение: экземпляр НЕ ПРОШЁЛ проверку работоспособности в текущем подключении. Вероятна аппаратная проблема модуля/его питания/контакта SDA; программно отличить дефект кристалла от обвязки и контактного соединения без измерений нельзя. Предыдущие два модуля на том же подключении работали. Для точной локализации нужны измерения питания у модуля и линии SDA/сравнение с исправным модулем; датчик не следует объявлять полностью исправным на основании одного ID. Поддержка ID0x9E сохранена, новый software workaround по ID не вводился: тот же ID был у ранее работавшего экземпляра.

Диагностика APDS_HEALTH_TEST находится в examples/basic/healthcheck.c и компилируется только с соответствующим флагом. APDS_I2C_TRACE выводит регистр и status при ошибке wrapper; I2C internals не изменялись. APDS_EXAMPLE_I2C_HZ позволяет временно менять частоту в примере. Все длительные журналы сохранены в test/evidence. Host suites после диагностических изменений:66197/66197/66197/648 checks, failures0.

На MCU оставлена завершающая health-прошивка: после HEALTH DONE опрос остановлен; выключить сам датчик командой не удалось из-за удерживаемой шины. Штатная конфигурация проекта и профили предыдущих датчиков не заменены экспериментальными настройками малого тока.
