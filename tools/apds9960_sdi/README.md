# Проверка APDS-9960 через SDI

Подключение на CH32V003: PC1 — SDA, PC2 — SCL, PD1 — SDI к WCH-LinkE.
Прошивка обращается к датчику по I²C (адрес `0x39`, 100 кГц).
WCH-LinkE принимает телеметрию по SDI и выводит её через свой виртуальный
COM-порт. Для этого теста выводы UART микроконтроллера не нужны.
[Руководство WCH-LinkE, раздел 5.2.11](https://www.wch.cn/uploads/file/20240829/1724894517211808.pdf)

Из корня репозитория в PowerShell:

```powershell
$diag = 'tools/apds9960_sdi'
$pioCore = "$env:USERPROFILE\.platformio"
$wlink = "$pioCore\packages\tool-wlink\wlink.exe"
pio run -d $diag
# Заменяет прошивку микроконтроллера.
& $wlink --chip CH32V003 flash --enable-sdi-print "$diag/.pio/build/apds9960_sdi/firmware.bin"
& "$pioCore\penv\Scripts\python.exe" "$diag/monitor.py" --port COM12 --log "$diag/.pio/sdi.log"
```

Отдельному Python нужен пакет `pyserial`. После переподключения
программатора включить SDI-вывод без перепрошивки можно командой
`wlink --chip CH32V003 sdi-print enable`.

В каждом цикле прошивка проверяет уровни SDA/SCL, 32 раза читает ID,
проверяет запись регистров по обратному чтению и снимает 100 выборок
приближения и RGBC. Затем она запускает режим жестов и считывает сырые
четвёрки каналов U/D/L/R из FIFO. Монитор ждёт полный цикл, печатает
диапазоны и возвращает 0 при успехе, 1 при ошибке диагностики, 2 при
ошибке подключения или истечении времени. Чтобы измерить реакцию оптики,
на несколько секунд поднесите ладонь к датчику и снова уберите её во время
съёма выборок. Проверка FIFO подтверждает получение сырых данных.
Распознавание направлений требует отдельного прогона с движением.

## Распознавание жестов библиотекой

Окружение `apds9960_gesture` собирает исходники APDS-9960 из этого пакета
и `I2C-CH32V003 v7.2.1`.
Приложение вызывает `apds_init()`, `apds_available()` и
`apds_readGesture()`. Направление в строке `RESULT` указано в координатах
драйвера. Настройки передаются через `build_flags` всему проекту.

| Параметр | Значение для экземпляра с ID `0x9E` |
|---|---|
| I²C | 100 кГц, опрос без INT (`APDS_INT_MODE=0`) |
| Пороги входа и выхода | `APDS_PROX_THRESHOLD=25`, `APDS_GESTURE_EXIT_TH=22`, автокалибровка отключена (`APDS_ENABLE_CALIBRATION=0`) |
| Канал приближения | `APDS_GAIN=2` (4×), `APDS_LED_CURRENT=2` (25 мА), `APDS_LED_BOOST=0` (100%) |
| Канал жестов | `APDS_CLONE_9E_PROFILE=0`, `APDS_GGAIN=1` (2×), `APDS_GLDRIVE=3` (12,5 мА), `APDS_GWTIME=1` (2,8 мс) |
| Декодирование | `APDS_GESTURE_TIMEOUT_MS=600`, `APDS_GESTURE_SENSITIVITY=3`, `APDS_FIFO_MIN_PACKETS=4` |
| Прочитанные регистры | `CONTROL=0x88`, `CONFIG2=0x01`, `GCONF2=0x39` |

Соответствие для ориентации платы во время проверки:

| Жест относительно наблюдателя | Результат `apds_readGesture()` |
|---|---|
| Влево | `GESTURE_UP` |
| Вправо | `GESTURE_DOWN` |
| Вверх | `GESTURE_RIGHT` |
| Вниз | `GESTURE_LEFT` |

Из корня репозитория, с теми же переменными `$diag` и `$wlink`:

```powershell
pio run -d $diag -e apds9960_gesture
& $wlink --chip CH32V003 flash --enable-sdi-print "$diag/.pio/build/apds9960_gesture/firmware.bin"
pwsh -NoProfile -Sta -File "$diag/gesture_trials.ps1" -Port COM12
```

Дай датчику 30 секунд измерить фон. На каждую зелёную стрелку сделай один
взмах в указанном направлении примерно в 4–7 см над датчиком. Выводи
ладонь за поле датчика в конце движения и возвращай вдали от платы.
Тест засчитывает один правильный результат на каждый сигнал.
Он отдельно регистрирует срабатывания вне сигнала и сбои драйвера.
Окружение `apds9960_gesture_debug` дополнительно пишет в SDI число
принятых FIFO-пакетов и разности сигналов по осям.

На плате с ID `0x9E` через COM12 эта конфигурация распознала 16 из 16
размеченных взмахов, по четыре в каждом направлении. За 20 секунд покоя
и между взмахами не было ложных жестов или ошибок драйвера.
В покое `PDATA` был в диапазоне 2–13. При предыдущих порогах 30/24
и чувствительности 5 распознано 18 из 20 взмахов, оба пропуска были вправо.

## Терминал жестов для Windows

Собранный `GestureTerminal.exe` лежит рядом с `firmware.elf` в
`.pio/build/apds9960_terminal/`. По умолчанию он подключается к COM12.
Если Windows назначила другой порт, передай его первым аргументом.

- **Начать тест** включает датчик и распознавание.
- **Остановить тест** останавливает опрос и выключает датчик.
- **Прерывания (INT → PC3)** переключает активный тест между опросом и
  аппаратным EXTI. Если тест остановлен, галочка задаёт режим следующего
  запуска. Переключать можно без перепрошивки.
- **Поворот** задаёт ориентацию корпуса в градусах. При 0° ИК-светодиод
  слева, вывод 1 вверху справа при взгляде со стороны оптики. Углы 90°,
  180° и 270° отсчитываются по часовой стрелке. Для положения платы из
  предыдущей проверки подходит 270°. [Даташит APDS‑9960, рис. 11](https://cdn.sparkfun.com/assets/learn_tutorials/3/2/1/Avago-APDS-9960-datasheet.pdf#page=17)
- Журнал показывает время, направление и значение `GESTURE_*`,
  которое вернула библиотека с учётом поворота, а также источник события.
  `EXTI` означает аппаратное прерывание, `PIN` означает чтение уже
  активной линии INT, `POLL` означает опрос по I²C.

Прошивка терминала использует тот же проверенный профиль APDS‑9960.
Терминал отправляет команды через WCH-Link по SDI и ждёт подтверждения
от прошивки. Поворот применяется в библиотеке через
`apds_setRotation(degrees)` и действует при следующем распознавании.
При сбросе микроконтроллера угол возвращается к 0°. Для приёма журнала
COM12 должен быть свободен.

Окружение apds9960_terminal собирается с исходниками библиотеки из этого репозитория.
Сборка приложения и прошивки из корня репозитория:

```powershell
pwsh -NoProfile -File tools/apds9960_sdi/build_terminal.ps1
```

Чтобы после сборки загрузить прошивку терминала на CH32V003, добавь
`-Upload`. Для запуска `GestureTerminal.exe` нужны установленный
PlatformIO с пакетами `tool-wlink` и `toolchain-riscv`, а также
`firmware.elf` от этой сборки в той же папке.
